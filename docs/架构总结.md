# 架构总结

## 项目概览

NanoBuddy 是一个基于 LLM 的智能 Agent 系统，采用 **分层架构** 设计，包含前端 SPA、FastAPI 服务层、nanobuddy Agent 引擎层和核心业务层。系统支持多用户认证、工作空间隔离、RAG 知识库、MCP 工具市场集成等核心功能。

## 数据流简图

### 对话数据流

```
用户 → index.html → sendChat() → POST /chat/stream
                                    │
                              adapter.chat_stream()
                                    │
                              AgentRunner.run(ReAct循环)
                                    │
                        ┌───────────┼───────────┐
                        ▼           ▼           ▼
                     LLM调用     Tool执行    记忆读写
                        │           │           │
                        └───────────┬───────────┘
                                    ▼
                              SSE事件流
                                    │
                ┌───────────────────┼───────────────────┐
                ▼                   ▼                   ▼
         think_token           answer_token           done
                │                   │                   │
         思考面板+状态条       AI回答气泡追加       清理计时器+状态
```

### 认证数据流

```
请求 → auth.py中间件 → 检查JWT/API Key → 获取用户 → 注入Request.state.user
                           │
                    无认证 → 创建Guest用户(readonly) → 注入Request.state.user
                           │
                    认证失败 → 返回401/403错误
```

### 文件访问数据流

```
请求 → _files_check_path() → use_workspace_for_user(u)
                                    │
                        ┌───────────┴───────────┐
                        ▼                       ▼
                   使用工作空间              不使用工作空间
                        │                       │
                  check_workspace_path()    check_path()
                        │                       │
                  assert_access(u)          assert_path_allowed()
                        │                       │
                        └───────────┬───────────┘
                                    ▼
                            返回resolved路径
```

## SSE 事件类型（/chat/stream）

| 事件 | 触发时机 | 前端处理 |
|:-----|:---------|:---------|
| `think_token` | LLM思考/工具调用（工具调用信息嵌在文本里） | 更新thinking-panel + status-bar |
| `answer` | 最终回答（每2个字符一个事件） | 追加到AI回答气泡 |
| `error` | 出错 | toast提示 |
| `done` | 流结束 | 清理所有badge + 停止计时器 |

> ⚠️ **注意**：工具调用**没有独立SSE事件**！tool_call/tool_result事件在 `/chat/stream` 路径上不存在。所有工具调用信息通过 `think_token` 事件以文本 "🔧 调用工具: xxx" 发送。前端通过解析 token 内容来识别工具执行状态。

## 记忆架构

nanobuddy 的记忆系统采用**分层设计**，实现长短时记忆结合：

```
┌─────────────────────────────────────────────────────────┐
│                      SOUL.md                             │
│            Agent身份定义（个性/目标/行为准则）             │
├─────────────────────────────────────────────────────────┤
│                      USER.md                             │
│            用户画像（偏好/历史/关系）                     │
├─────────────────────────────────────────────────────────┤
│                      MEMORY.md                           │
│            长期记忆（重要事实/经验/知识）                 │
│            ← Consolidator自动总结压缩                    │
├─────────────────────────────────────────────────────────┤
│                    history.jsonl                         │
│            短期记忆（对话历史，最近N条）                  │
│            ← 超过阈值自动触发Consolidator                 │
└─────────────────────────────────────────────────────────┘
```

**MemoryStore**（`nanobuddy/agent/memory.py`）：文件IO层，管理 MEMORY.md、history.jsonl、SOUL.md、USER.md 的读写

**Consolidator**：记忆压缩器，当历史记录超过阈值时自动总结并写入 MEMORY.md

## 认证与权限体系

### 用户角色

| 角色 | 权限 | 说明 |
|:-----|:-----|:-----|
| `admin` | 全部权限 | 管理员，可访问所有资源 |
| `member` | 读写权限 | 成员，可访问工作空间内资源 |
| `guest` | 只读权限 | 访客，默认角色，仅浏览 |

### 认证流程

```
1. 用户访问页面 → 默认进入guest模式（无需登录）
2. 点击"登录" → 输入用户名密码 → POST /api/auth/login
3. 服务端验证 → 返回JWT Token → 存储到localStorage
4. 后续请求 → 自动携带Authorization: Bearer {token}
5. 服务端中间件 → 解析Token → 验证用户身份 → 注入Request.state.user
6. 页面刷新 → 从localStorage恢复Token → 保持登录状态
```

## 路径安全策略

系统通过 **沙箱机制** 确保文件访问安全：

### 核心函数

| 函数 | 位置 | 作用 |
|:-----|:-----|:-----|
| `check_workspace_path()` | `core/path_policy/workspace.py` | 检查工作空间内路径合法性 |
| `assert_access()` | `core/path_policy/workspace.py` | 验证用户对路径的访问权限 |
| `check_path()` | `core/path_policy/policy.py` | 检查基础路径合法性 |
| `get_allowed_roots()` | `core/path_policy/policy.py` | 获取允许访问的根目录列表 |
| `is_sandbox_enabled()` | `core/path_policy/policy.py` | 检查沙箱模式是否启用 |

## 关键设计决策

### 1. 双引擎并存

- **nanobuddy**：新引擎，ReAct循环，完整工具系统，记忆管理
- **CoreAgent**：旧引擎，逐步迁移到nanobuddy

### 2. 工作空间隔离

每个用户有独立的工作空间目录，共享目录供团队协作

### 3. 默认只读模式

系统默认以guest角色启动，用户需主动登录才能获得更高权限

### 4. SSE流式响应

对话采用SSE流式传输，实现实时打字效果和思考过程展示

### 5. 多模型支持

通过Provider模式支持多种LLM：Ollama、OpenAI、Anthropic、Azure等
